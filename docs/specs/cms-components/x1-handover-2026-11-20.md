## The goal

The only time we use variants is when we're changing simple things, like maybe text alignments or showing or hiding one or two elements... What you're doing is you're changing whole entire layouts."

Done means:
- Every variant that changes layout is its own component, named for what it is (e.g. "Split Image Text Edge"). Classes stay shared (one class family per component family; differences are combo classes).

## Hard-won gotchas (each one cost an hour tonight)

1. **Publish can fail silently.** `publish_site` returns success even when Webflow refuses the publish. After every publish, poll `GET /v2/sites/6ad6405eae8eac6d7b7c41a3` until `lastPublished` moves past the time you published. If it does not move within about two minutes, there is probably an invalid style (see 2). One publish per minute at most; on a 429 wait and publish once.
2. **Unlinking or copying variant styles can truncate `url(...)` values** to `url("https`, which makes every publish fail with a CSS error. After any style copy, query the new combo classes for `background-image` at every breakpoint (`include_breakpoints`; property filters only check the base breakpoint) and restore full values from `get_variant_styles`. Details: `docs/solutions/integration-issues/webflow-unlink-truncates-url-values.md`.
3. **Prefer building the new component from styles over unlinking instances.** Unlinking a variant instance creates generated combo names ("Blue 3", "Image Bg 40"); those break the naming rules and caused gotcha 2. Duplicate the component, then write the chosen variant's styles into properly named combo classes.
4. **Swapping an instance:** `insert_component_instance` with `creation_position: "before"` the old instance's element ID, copy prop values with `get_component_instance_props` then `set_component_instance_prop_values`, then remove the old instance. Inserting `after` an instance fails ("Cannot insert elements directly into a component instance"); use `before`.
5. **Filling an empty slot:** `data_component_builder` `insert_in_slot` (by slot name) a temporary Div, `move_element` the real element before it, remove the Div. Slotted child IDs are `{component: <pageId>, element: <id>}`.
6. **Collection Lists inside a component definition cannot be configured headlessly** ("No source connected" / "not inside a CMS context"), and lists inside slots reject settings writes. Configure lists on the page first, then move them in. If a step truly needs the Designer, list it as a click step for Stephen.
7. **Option fields** bind only to text; they cannot drive visibility or variants.
8. **Attributes:** `set_settings` `attributes` replaces the whole list; read first and re-include the static ones.
9. **Instances on CMS template pages** (`/rooms/<slug>`, `/dining/<slug>`, legal) count too; check one real item page for each.
