# Ticket 234: subnav dropdown opens with an eased height and staggered links (M19)

## What changed

- `src/utils/tabDropdown.ts`: `setOpen` now animates with GSAP. Open: the panel's height and top padding ease (0.45s, power3.out) from the 40px pill row to full height, then the links fade and rise in with a 0.06s stagger, starting at 40% of the height tween. Close reverses it (links out in reverse order, then the height collapses). Reduced motion (`prefers-reduced-motion: reduce`, read at click time) opens and closes instantly.
- `aria-expanded` flips immediately and an `expanded` flag drives toggle, Escape and outside clicks; `is-open` stays until a close tween ends, with `is-closing` marking that window so the X icon swaps back at once. Escape still returns focus to the toggle.
- Links use `autoAlpha` (visible and clickable from the first frame of their fade), animating to their CSS opacity (0.62 inactive, 1 active). Inline `height`, `paddingTop`, `opacity`, `visibility` and `transform` are cleared when each tween ends. No inline `display: none`.
- Interrupted open or close kills the running tweens and continues from the current height.
- ScrollTrigger: the bar stays 40px and the panel is absolute, so page height never changes. No refresh call is needed (and none is made).
- Panel gets `overflow: hidden` while open, so the growing panel clips its links.
- `docs/reference/runtime-modules.md`: M19 paragraph added to the tabDropdown entry.

## Tests

`tests/visual/tab-dropdown.spec.ts` with `fixtures/tab-dropdown.{html,ts}` (390px viewport):
