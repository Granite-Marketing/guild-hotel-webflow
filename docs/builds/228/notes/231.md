# Ticket 231: sticky "Reserve a table" (M21, M22)

## Cause of the hidden state (M21)

Reproduced on the staging Dinings page (`/dining/dining-gardenterrace`) with Playwright.

- The phone hero is 800px tall (taller than most phone screens). The button sits at its foot, 780px from the top, so on a screen shorter than that it starts below the fold.
- `stickyCta` only docked the button once its own spot had risen above the dock line, and its first-screen branch (`gapAtTop > 0`) only covers a button that starts on screen. A below-the-fold button was left in place, out of sight, until the visitor scrolled about 100px. At 390x700 the button was at y=780 on load and became `position: fixed` only after a scroll of 300px (y=631).
- Also seen at 390x700 after load: the `is-stuck` class was on while the inline `position: fixed` was gone (empty `style`). The hero line mask also animates this button (it wraps it and tweens its transform), and the docked state was kept in inline GSAP styles, so the two writers disagree. At 390x844 and 1440 the button was docked and visible.
- Why the earlier fixes did not hold: 22c750b (F10) built the dock; 849a6b3 (v1.1.30) and 27aeb5a made a first-screen button dock from load, but only for a button already on screen; 350ba63 (2026-11-12) lifted the hero's z-index layer and added the "Other dining options" end. All three fixed stacking or the on-screen case. None covered a button that starts below the fold, which is the phone case. I could not find a document that records the cause of the earlier "hidden until scroll" report (docs/feedback/*.md only has the M21 entry).

## Fix

- `src/utils/stickyCta.ts`: new option `dockFromLoad`. When on and the button's spot is below the first screen, the dock trigger starts at load (-1, because ScrollTrigger treats progress 0 as inactive). The docked state is now an attribute and class styled by an injected stylesheet (`position: fixed`, `translate: -50% 0`, bottom from a CSS variable) instead of inline GSAP styles, so the line mask's transform and style writes cannot undo it. Every ScrollTrigger refresh re-applies it. The desktop settle tween animates the CSS variable.
- `src/index.ts`: the Dinings call passes `{ dockFromLoad: true }`. The story "Learn more" call is unchanged (it must dock only as it nears the screen).
- M22: the Dinings call already ended at `.section_card-carousel-header-left` (since 350ba63), so the button already hides at "Other dining options". The test now covers it, including returning on scroll back up.

ASSUMPTION: "Other dining options" is `.section_card-carousel-header-left` (Dinings template carousel; `docs/reference/site-head/other-dining.css` and index.ts name it). The first match in the page is used.

## Tests

`npx playwright test tests/visual/sticky-cta.spec.ts` (8 tests, 390 and 1440 at 700px high, hero taller than the screen): on screen on first load before any scroll; stays above a later z-indexed section; hides at "Other dining options" and returns on scrolling up; survives its inline style being rewritten plus a refresh. Against the old module the first-load and style-rewrite tests fail.
