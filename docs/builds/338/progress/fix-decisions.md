## Round 1
- Swap split text by calling the instance's public `split()` with a registry-owned `onRevert` hook that writes the new text, instead of revert-then-recreate; alternatives: replace the element node and build a fresh SplitText (breaks every module's element reference and leaves a stale observer on the old node), wrap text in an inner split host (changes DOM and aria-label placement); why: SplitText 3.13 `split()` restores its stored markup, calls `onRevert`, then re-reads the element, so the new text becomes the instance's own original and later autoSplit re-splits (resize, font load) keep it; no manual `.revert()` anywhere; landed: src/utils/splitRegistry.ts
- `trackSplit` takes the SplitText options instead of a create function, so the registry can add its hooks; alternatives: keep create() and patch vars after (private); why: the three callers are all in this branch; landed: src/utils/splitRegistry.ts, heroTextReveal.ts, lineMaskReveal.ts, scriptReveal.ts
- After a content re-split, restart the onSplit animation only when it is not scroll-driven; alternatives: always restart, never restart; why: SplitText carries the old animation time into the new one, so the hero reveal would not replay (DN1 requires it), while a scroll-driven reveal should keep its scroll state; landed: src/utils/splitRegistry.ts
